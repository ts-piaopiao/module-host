# productContext — 项目存在的原因与体验目标

> 回答「为什么做、给谁用、什么算好」。需求或体验目标变化时更新本文件。

## 1. 项目要解决的问题

module-host 是一个**分阶段落地的模块宿主系统框架**：宿主 `core.exe` 负责加载插件、
跑闭环、做输出；插件负责「看」（capture）和「判」（policy）；宿主内另有一层
**可替换的决策脚本**（`IScript` / `CppScript`），真正产出按键动作。

它要解决的具体问题是：

1. **契约脆弱**：宿主与插件之间只要头文件不锁死，ABI 漂移就会导致加载失败且难排查。
   → 用 `core_contract.h` 单头 + 编译期断言把契约**先锁死**。
2. **错误路径不可回归**：缺 DLL / 缺符号 / ABI 不匹配 / 元数据无效 / init 失败 /
   运行期 decide 失败，这些若只靠人工试，迟早漏测。
   → 把每条错误路径做成**可一键重放的验收场景**。
3. **决策逻辑无法离线验证**：打怪状态机一旦进真机，只有「跑跑看」一种验证手段。
   → 决策层从 policy 中剥离出来，做成可替换脚本，用 `experiments/script_replay`
   **离线回放录制 JSONL**，逐字节比对 trace 输出（SHA256）。
4. **运行时不可观测**：真机跑起来后，状态机在想什么、锁的是谁，外界看不到。
   → 遥测接口 + Web 前端（`telemetry_server` + 画布），且**换 UI 实现不重编 core**。

## 2. 使用者与场景

| 使用者 | 场景 | 关注点 |
|---|---|---|
| 开发者（本机） | 改代码 → `scripts\run_all.ps1` → 看 11 步全绿 | 回归速度、错误信息可读性 |
| 决策层开发者 | 录制/构造 fixture → `script_replay.exe` → 比对 trace SHA256 | 逐字节确定性、seed 固定 |
| 真机调试者 | 起 `core.exe` → 浏览器开 `http://localhost:6601` | 状态机、锁定、决策是否符合预期 |
| 排障者 | 读 `docs/env-traps.md` | 是否已经有人踩过这个坑 |

## 3. 用户体验目标

### 3.1 验收体验

- **一条命令全量验收**：`scripts\run_all.ps1`，无需硬件，任何机器可跑。
- **失败即定位**：每步输出 `PASS/FAIL + exit + keyword + reason`，
  `SUMMARY: contract=PASS off_build=PASS ... result=PASS` 一眼看全。
- **确定性**：同一个 seed（`MH_SCRIPT_SEED=42`）必须产出**相同 SHA256** 的 trace；
  「变了没变都是有效结论，如实报告」，不允许猜测。

### 3.2 运行期体验

- **UI 挂了 core 照跑**（原则 U1）：前端断线只影响观察，不影响决策与输出。
- **断线 1 秒自动重连**，回放场景下断线**不清空本地缓冲**（UI-3c-2 修复）。
- **字段与 recorder 对齐**（原则 U6）：实时流与 JSONL 回放共用一套解析，
  前端不需要为两种来源写两套代码。

### 3.3 可维护性目标

- **UI 实现可替换**：core 只暴露稳定遥测接口，前端无框架（原生 JS + Canvas）。
- **决策层可替换**：`IScript` 抽象，`CppScript` 是实现之一，可整体换掉。
- **错误路径可扩展**：新增一类错误 = 新增一个 bad_plugin 目录 + 一条验收场景。

## 4. 判据（什么算做完了）

1. `scripts\run_all.ps1` **11/11 全绿、exit=0**。
2. 阶段 1 **11 场景**、阶段 2 **5 场景**、script **6 fixture I1–I11 全 PASS**。
3. 契约若变更：`docs/contract-change-procedure.md` 流程走完，所有插件重新验收。
4. 文档与代码**必须一致**——描述与实现不符按 bug 处理（本项目已多次因此返工）。
5. 改动后 `activeContext.md` / `progress.md` 同步更新。

## 5. 明确的「好」与「不好」

| 好 | 不好 |
|---|---|
| 先给 Implementation Plan 再动手 | 没确认就改代码 |
| 贴回实际代码/实际 SHA，如实报告 | 猜测、期望某个结果 |
| 同类问题一并修并**明确报告 old/new** | 悄悄扩大改动范围 |
| 新坑追加进 `docs/env-traps.md` | 只在会话里说一句就丢掉 |
| 单开一包做一件事 | 把多个验收目标混进一个 commit |
